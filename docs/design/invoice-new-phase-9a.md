# الخطوة 9أ — إنشاء فاتورة المبيعات: الواجهة والمراجعة

تنفيذ محلي بتاريخ 2026-10-01. النطاق مقسوم إلى 9أ (منجزة) و9ب (التحصيل والحفظ المالي، معلقة) وفق طلب العمل على مراحل.

## التغييرات

- توسيع مساحة الإنشاء، العميل والتواريخ والبنود والملاحظات يميناً، ملخص الخصم والتحصيل يساراً، وبطاقات بنود للهاتف.
- بحث الزبون بالاسم والهاتف والمنتج بالاسم وSKU والباركود، مع تجاهل نتائج الطلبات القديمة وإظهار فشل البحث. Enter يضيف تطابق رمز واحد من النتائج المحملة.
- إضافة منتج تستبدل البند اليدوي الفارغ، وإخفاء تكلفة وربح البنود خلف خيار عرض داخلي (ليس بديلاً عن صلاحيات البيانات).
- حساب المبالغ إلى منزلتين، خصم ثابت أو نسبة، والتحقق من القيم غير المحدودة والكميات والتواريخ والخصم الزائد.
- عرض واضح للدفع النقدي الكامل أو البيع الآجل، مع زبون مسجل إلزامي للبيع الآجل. لم يعد النموذج يعرض مبلغاً جزئياً ثم يتجاهله ويسجل النقد كاملاً.
- مراجعة قبل التأكيد؛ تغيير المدخلات يلغي المراجعة. الحفظ محمي من الإرسال المتكرر أثناء الطلب ومن الإعادة بعد إنشاء رأس الفاتورة في نفس جلسة النموذج.
- مسودة محلية صريحة في sessionStorage لكل متجر ومستخدم؛ لا تنشئ فاتورة في قاعدة البيانات ولا تؤثر في المخزون. لا تنتقل بين الأجهزة.
- التحقق من الفترة والزبون والمنتجات والترقيم قبل بدء الكتابة، وفحص أخطاء البنود والتحديثات المتأخرة والترحيل، مع رابط مراجعة للفاتورة المنشأة عند فشل الإكمال.
- الفاتورة الآجلة المعتمدة تستخدم sent بدلاً من draft لتمييزها عن المسودة.

## التحقق

- npm run build وفحص TypeScript ناجحان.
- 3 اختبارات: الخصم الثابت والنسبة، التقريب والكمية الكسرية، ورفض القيم والتواريخ غير الصحيحة.
- متصفح ببيانات توضيحية وحفظ معطل: إجمالي البنود 160، خصم 10، مستحق 150. بدون دفعة: مدفوع صفر ومتبقٍ 150. حفظ واستعادة مسودة بعد تغيير الخصم؛ تأكيد المعاينة يعرض منع الحفظ دون إرسال معاملات.
- صور invoice-new-desktop.jpg وinvoice-new-mobile.jpg؛ عرض الهاتف 390 يساوي عرض المستند دون تجاوز أفقي.
- فحص قراءة فقط لأعمدة المنتجات والفواتير المنشورة. يستخدم عميل فحص إداري ولا يثبت صلاحيات RLS.
- /design-preview/invoice-new للتطوير فقط. لم تسجل فاتورة أو دفعة حقيقية ولم ينشر المشروع.

## المتبقي في 9ب

مسار الإنشاء القديم يكتب الفاتورة والبنود والمخزون والذمة على عدة طلبات غير ذرية، ويسجل amount_paid للنقد دون سند قبض مطابق. لا تعتبر هذه الواجهة إصلاحاً لذلك المسار. الدفعة الجزئية معطلة حتى يربط الحفظ والتحصيل بسند قبض وحركة صندوق وترحيل صحيحين، مع معالجة التكرار على الخادم والتزامن وترقيم الفواتير.

يجب أيضاً مراجعة التحويل من الطلبية لمنع خصم مخزون سبق صرفه، وتحديث تكلفة البنود المحولة من المنتجات، واختيار الصندوق، وتاريخ القبض، والطباعة بعد الحفظ. الملاحظات الداخلية حقل منفصل غير متاح في هذا النموذج. الطباعة تتم من صفحة الفاتورة الحالية.

نقطة الاستكمال: 9ب قبل الانتقال إلى قائمة الفواتير (10).
