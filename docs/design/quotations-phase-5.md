# المرحلة الخامسة: عروض الأسعار

صفحة الإنشاء: ملخص جانبي، أقسام قابلة للوصول، مراجعة البنود، حفظ كمسودة، إصدار بعد اكتمال إدراج البنود، تواريخ فلسطين، وإلغاء اختيار عميل تلقائي. لا تدّعي الشروط الافتراضية أن الضريبة مشمولة؛ الإجمالي يبقى مجموع البنود وفق السلوك المحاسبي القائم.

قائمة العروض: بحث بالاسم والرقم والهاتف، شهر الإصدار، حالات مع أعداد، صلاحية محسوبة حتى نهاية اليوم المحدد، ترقيم صفحات، ملخص منفصل لكل عملة دون المسودات. الاستعلام يجلب جميع الصفحات لتجنب حد 1000 سجل. أخطاء التحميل تظهر بدلاً من قائمة صفرية صامتة. رابط التحويل يظهر للعروض المرسلة أو المقبولة السارية؛ الواجهة تستخدم مسار الفاتورة الموجود.

الحفظ القائم ليس معاملة ذرية: تنشأ المسودة أولاً، ثم البنود ثم تحديث حالة الإصدار. عند فشل البنود أو تحديث الحالة يُمنع تكرار الإرسال في النموذج، ويعرض رابط القائمة لمراجعة المسودة. تعذر حفظ منتج حر أصبح خطأ واضحاً. لم نختبر الحفظ الحقيقي أو إنشاء فاتورة على بيانات المتجر ولم نغير مخطط قاعدة البيانات.

التحقق: بناء الإنتاج وTypeScript ناجحان، اختباران للتحقق من الكميات والأسعار والتواريخ وحساب الصلاحية ناجحان. استعلام عروض الأسعار والعلاقة مع العميل نجح بالقراءة فقط. المعاينة أظهرت إجمالي 7600 عند تغيير كمية منتج سعره 3800 إلى 2. البحث ومسح الفلاتر نجحا، الهاتف 390px دون تجاوز عرض الصفحة. الجداول تتمرر أفقياً داخل حاويتها.

معاينة تطوير فقط: /design-preview/quotations و?view=new. حفظ المعاينة لا يكتب أي بيانات. صور التوثيق بجانب هذا الملف.

المراحل التالية: إدارة الزبائن وحسابات العملاء وفق الصور الجديدة. POS وفواتير المبيعات ما زالت ضمن الطلب السابق ولم تنفذ في هذه المرحلة. لا نشر أو التزام Git.
