# المرحلة 22ب2 — مرفقات التحويل الخاصة

اكتملت في 2026-10-04. طُبق الترحيل 061 على قاعدة البيانات والتخزين. كود التطبيق محلي ولم يُنشر.

## السلوك

يحفظ نموذج القبض السند المالي أولاً، ثم يظهر قسم لرفع المرفقات المختارة. يظهر القسم أيضاً عند فتح سند قبض بنكي محفوظ للمالك أو المدير النشط، لاستكمال الرفع بعد إغلاق الصفحة أو انقطاع الشبكة. اختيار الملفات لا يرفعها، وحفظ السند لا يعني اكتمال مرفقاته. لا يتكرر القبض عند إعادة رفع الملفات، ولا تُلغى المعاملة المالية إذا فشل رفع ملف. المرفقات متاحة من السند المرتبط بالفاتورة، ولا تظهر في مستند طباعة السند ولا في نسخة العميل.

كل ملف يحجز سجلاً بحالة pending قبل أي كتابة في التخزين. مساره ثابت من المتجر والسند وبصمة SHA-256 للمحتوى؛ الرفع لا يستبدل ملفاً موجوداً. يتحقق الخادم من النسخة المخزنة ومطابقة بصمتها وحجمها قبل اعتماد ready. إذا فقد رد الرفع أو رد اعتماد البيانات، يظل الحجز قابلاً للاستئناف بالملف نفسه؛ إعادة رفع ملف مكتمل لا تنشئ نسخة أخرى. حجوزات الرفع غير المكتمل ظاهرة للمستخدم وتحسب ضمن الحدود، لتجنب تراكم ملفات غير متتبعة أو تجاوز الحدود. لا توجد مهمة حذف تلقائي للحجوزات أو الملفات؛ الاستئناف يتطلب الملف الأصلي عند إغلاق الصفحة.

## الصلاحيات والحدود

- مساحة receipt-attachments خاصة، وحماية تقييدية تمنع القراءة والرفع والتعديل والحذف المباشر لحسابات anon وauthenticated حتى بوجود سياسة قديمة واسعة.
- حجز الملف عبر دالة موثقة يتحقق من المالك أو المدير النشط، والمتجر وسند قبض بنكي ذري محفوظ. الموظف وصلاحية الصندوق النقدي لا تمنحان الوصول.
- بيانات المرفقات تخضع لـRLS؛ لا يمكن للمستخدم اعتماد الحالة أو تعديلها مباشرة. خادم التطبيق يستخدم صلاحية الخدمة بعد نجاح التفويض.
- التنزيل يمر عبر رابط في التطبيق يعيد فحص جلسة المستخدم والمتجر وRLS قبل جلب الملف. لا روابط عامة أو روابط موقعة قابلة للمشاركة. الاستجابة private/no-store وnosniff وتنزيل إجباري مع sandbox.
- حتى خمسة ملفات، 5 MiB لكل ملف و15 MiB إجمالاً؛ حجز الملفات متسلسل لكل سند لمنع تجاوز الحدود المتزامن. يرفع الخادم ملفاً واحداً في كل طلب، وحد Server Actions هو 8 MiB لتغطية الملف وبيانات الطلب.
- يسمح بـPDF/JPEG/PNG/WebP مع تحقق الحجم والاسم وتوقيع النوع ونهاية الملف وبصمة المحتوى. هذا تحقق بنيوي محدود، وليس فحصاً مضاداً للبرمجيات الضارة أو تحليلاً كاملاً لمحتوى PDF والصور.

## التحقق

- 56 حالة تكامل تشمل المعاملة البنكية السابقة وحجز المرفقات وتكرار الحجز والحدود والصلاحيات وحماية مساحة التخزين أمام سياسة اختبار واسعة. كل بيانات الاختبار وDDL داخل معاملة تم التراجع عنها بالكامل؛ لا مستندات مالية تجريبية متبقية.
- 27 اختباراً محلياً: 14 للمراجعة والعرض، و8 للمحتوى وإخفاقات الرفع وإعادة المحاولة، و5 لحدود خادم الرفع والتنزيل ومنع استخدام عميل الخدمة قبل التفويض.
- اختبار Storage API فعلي ببايتات PDF اصطناعية صغيرة: نجاح الرفع والتنزيل للخدمة، رفض التنزيل والرفع المجهول، ورفض رابط public. حُذف ملف الاختبار عبر Storage API وتأكد عدم بقائه. لا كتابة مالية.
- تحقق API بعد الترحيل: دالة الحجز متاحة وترد برفض الطلب دون هوية مستخدم، دون كتابة بيانات. رابط التنزيل المحلي دون جلسة يرد 401.
- معاينة قسم المرفقات على الحاسوب والهاتف، بعرض 390px دون تجاوز أفقي. المعاينة تمنع الرفع، ولا تدعي حفظ مستند حقيقي. الصور: receipt-attachments-desktop.jpg وreceipt-attachments-mobile.jpg.
- TypeScript وبناء Next.js ناجحان (105 صفحات ثابتة؛ مسار تنزيل ديناميكي جديد).

مرجع اختيار مساحة خاصة وتفويض الوصول: [توثيق Supabase للتخزين الخاص](https://supabase.com/docs/guides/storage/buckets/fundamentals).
